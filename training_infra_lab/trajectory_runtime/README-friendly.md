# Qwen3.5-9B GRPO 运行时

## 这个项目解决什么问题

项目实现一条可审计的同步 GRPO 训练链路：

```text
当前策略采样
→ 规则奖励
→ 完整 prompt group 的 advantage
→ 全 rank 训练计划
→ FSDP2 反向和 Adam 更新
→ 轨迹、参数版本和状态证据归档
```

重点不是训练一个更强的数学模型，而是证明采样、奖励、分布式更新和优化器状态之间没有断链。

## 当前结论

| 问题 | 结果 |
|---|---|
| Qwen3.5-9B 能否在 4×H20 上全参数更新 | 能；FSDP2、BF16 计算、FP32 master/归约 |
| 生成期权重驻留是否减少开销 | 能；v8 的 128-token 生成阶段中位 1.761× |
| 长度排序计划是否更快 | 没有稳定收益；中位 0.988× |
| 严格奖励能否产生真实更新 | v9 第四步由两条明确错答产生非零梯度和 Adam 状态 |
| 是否证明模型能力提高 | 没有；只有一次严格奖励下的非零梯度更新 |
| 910B4 是否已完成新模型验收 | 没有；探针尚未获得运行结果 |

## v8 和 v9 为什么都要保留

v8 完成了四次非零梯度更新和生成性能对照，但旧奖励规则只取最后一个数字。64 条轨迹中有 34 条截断，其中 4 条截断轨迹因中间数字碰巧等于参考答案而被判对。因此 v8 适合回答执行和性能问题，不适合回答奖励质量问题。

v9 改为：

- 只有正常 EOS 才能得分；
- 最后一行必须是 `Final answer: <number>`；
- 分开记录正确、明确错答、格式失败和截断。

v9 的 64 条回答全部正常结束：62 条正确、2 条明确错答。前三步组内奖励全同，所以梯度和 Adam 矩为零；第四步有一个组出现正确与错误回答，梯度范数为 0.915452。
