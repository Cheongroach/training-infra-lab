# 03 回答、奖励与轨迹审计

## 诊断问题

训练使用的回答是否完整、奖励是否可独立复算、组内是否存在真实学习信号？

## 输入参数

| 参数 | 含义 |
|---|---|
| `trajectory_id` | 每条回答的唯一身份 |
| `prompt_group_id` | 同题回答组 |
| `policy_version` | 生成时策略版本 |
| `input_ids` / `response_mask` | token 与响应位置 |
| `old_log_probs` | 生成时行为概率 |
| `text` | 原始回答 |
| `finish_reason` | `eos` 或 `length` |
| 固定参考答案 | 独立重评分输入 |
| reward rule version | 评分规则身份 |

## 操作步骤

1. 按 trajectory ID 对齐 rollout 文件和 learner batch。
2. 检查每个 prompt group 的成员数完整且没有重复身份。
3. 检查 response mask 数量与保存的 response token 数一致。
4. 检查行为概率长度、有限性和响应 token 一一对应。
5. 使用原始回答、结束原因和固定参考答案独立重算奖励。
6. 将结果区分为 `correct`、`incorrect`、`missing_final_answer`、`truncated`。
7. 在完整回答组上重新计算相对优势。
8. 统计有非零相对优势的回答组。

## 输出结果

v9 的实际审计输出为：

| 项目 | 结果 |
|---|---:|
| 轨迹数 | 64 |
| 正确 | 62 |
| 明确答错 | 2 |
| 格式失败 | 0 |
| 截断 | 0 |
| 有学习信号的更新 | 仅第 4 次 |

两条错误回答自然结束并输出 141；同组另外两条输出正确答案 13。

## 最终诊断结论

v9 第四次更新的零奖励来自完成后的真实答错，不是截断或格式失败，因此该回答组构成有效组内学习信号。前三次更新所有回答奖励相同，不能称为非零学习更新。

## 原理说明

GRPO 的信号来自同题回答之间的相对差异。只要整组奖励相同，相对优势就是零。结束原因必须参与评分，否则截断推导中的中间数字可能被误判为最终答案。训练时保存的 reward 也不能作为唯一证据，应由独立代码从原始文本重算。

## 注意事项

- 不能先按 rank 分片再计算组内相对优势。
- 不得把截断当作明确数学错误。
- 不得事后重打分后冒充原训练的 on-policy reward。
- 回答正确率属于当前采样批，不是训练后 held-out 准确率。
