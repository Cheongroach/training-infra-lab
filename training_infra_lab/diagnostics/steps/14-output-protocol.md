# 14 输出格式与评分协议诊断

## 诊断问题

回答已经自然结束并含有可见 boxed 数值时，为什么固定 scorer 仍可能解析失败？

## 输入参数

| 参数 | 设置 |
|---|---|
| prompts | 冻结的 4 条题目 |
| temperature | 0 |
| thinking | disabled |
| max response | 4096 token |
| required version | 3 |
| raw finish reason | 必须为 stop/EOS |
| scorer | 冻结 DAPO 提取与评分代码 |
| required answer shape | 最终 `\boxed{...}` |

## 操作步骤

1. 保存原始回答，不先做文本改写。
2. 检查自然 EOS 和匹配的停止 token。
3. 检查行为概率和版本 span 覆盖全部响应。
4. 提取最后一个闭合、非空 boxed 表达式。
5. 调用冻结 scorer 获取 `pred` 和 reward。
6. 离线使用同一 scorer 重评分并与运行记录比较。
7. 将“自然完成”“boxed 存在”“scorer 可解析”“答案正确”分别报告。

## 输出结果

四条回答全部自然结束并消费版本 3，也都有闭合 boxed 表达式。结果：

| index | boxed | scorer pred | 协议 |
|---:|---:|---|---|
| 0 | 54 | 54 | 通过 |
| 1 | 13 | 13 | 通过 |
| 2 | -1 | 空 | 失败 |
| 3 | 5 | 空 | 失败 |

失败回答把 `Final Answer:` 放在一行，下一行才输出 `$$\boxed{...}$$`。冻结正则只捕获冒号同一行内容，因此归一化为空。

## 最终诊断结论

训练更新和版本发布通过，但最终回答协议失败。问题位于生成文本格式与 scorer 接口，不是 GPU 数量、NCCL、OOM 或权重发布。官方评分 0/4 是该冻结协议下的结果，不是独立能力评测。

## 原理说明

人类可见的数学答案与程序解析事件不是同一对象。固定 scorer 定义了精确语法接口；自然 EOS 只说明回答完成，boxed 存在只说明文本包含候选答案，只有 scorer 成功解析后才能进入固定评分。

## 注意事项

- 不得为通过验收而事后切换 scorer 模式。
- 格式失败和数学错误必须分开。
- 更多 GPU 不会修复正则协议。
- 提示、scorer 或答案格式任一变化都应作为新实验。
