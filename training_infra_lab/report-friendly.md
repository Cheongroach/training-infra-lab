# H20 / 910B4 全参数 SFT：读者版报告

## 研究问题

在不改变训练目标的前提下，Qwen2.5-1.5B 全参数 SFT 能否：

1. 同时运行在 H20/CUDA 和 Ascend 910B4/CANN；
2. 降低 padding、输出层和 activation 的显存开销；
3. 减少梯度累积期间的通信；
4. 扩展到两机 16×H20；
5. 从 checkpoint 恢复出与不中断训练一致的状态。

这是训练基础设施实验，不是模型能力或长程收敛研究。

## 实验设置

模型有 1,543,714,304 个可训练参数，使用 28 层 Qwen2 decoder。训练数据来自 `HuggingFaceH4/no_robots`，损失只监督 assistant token。主实验使用 global batch 8、microbatch 1；强扩展固定 global batch 16。

训练保留 FP32 参数和 Adam 状态，BF16 前向，FP32 梯度归约。H20 和 910B4 使用不同软件栈，因此绝对速度只描述本次环境，不能当作硬件总体排名。

## 先证明目标没有改变

一次 optimizer step 的目标是所有 rank、所有 microbatch 的监督 token loss 总和，除以全局监督 token 数。不能先对每个 microbatch 求平均再相加，否则短回答会获得过高权重。

正确性检查覆盖：

- assistant 标签边界和因果移位；
- full、selected、chunk 三种输出层路径；
- 不等长样本和全忽略标签；
- FSDP2 梯度及一次参数更新；
- 延迟梯度同步；
- 参数、Adam、RNG 和数据位置恢复。

小模型数值检查不等于 1.5B 模型逐位相同。1.5B 的逐字节比较只在确定性恢复实验中完成。

## 主要结果

### 1. 最大收益来自减少 padding

| 配置 | 2×H20 token/s | H20 GiB/卡 | 2×910B4 token/s | 910B4 GiB/卡 |
|---|---:|---:|---:|---:|
| 固定 4096，full | 1,318 | 31.59 | 1,089 | 31.53 |
| 动态，full | 2,758 | 16.31 | 1,724 | 16.34 |
| 动态，selected | 2,878 | 14.75 | 1,719 | 15.09 |
| 动态，chunk | 2,836 | 15.28 | 1,699 | 16.13 |
| 动态，chunk + AC | 2,036 | 13.51 | 1,679 | 14.29 |

固定 4096 的 padding 比例为 92.1%，动态 padding 后为 16.2%。因此最大的变化不是新 kernel，而是停止计算大量补齐位置。

`selected` 只在有监督的位置计算输出投影，稳定降低显存。`chunk` 通过重算限制临时 logits，但在这批短样本上没有稳定优于 `selected`。Activation checkpoint 进一步省显存，同时可能降低吞吐。

### 2. 延迟梯度同步减少了 ReduceScatter

默认每个 microbatch 都同步梯度；延迟方案只在最后一个 microbatch 执行 reduce-scatter。

H20 profiler 中，单步 ReduceScatter 从 116 次降至 29 次，AllGather 仍为 232 次。这说明优化减少的是梯度通信，不是参数聚合。

| 后端 | 默认同步 token/s | 延迟同步 token/s | 额外显存 |
|---|---:|---:|---:|
| 2×H20 | 2,880 | 3,256 | +2.88 GiB/卡 |
| 2×910B4 | 1,727 | 2,476 | +2.88 GiB/卡 |

H20 只有两次短测且波动较大；13.1% 只能称为本次观察。910B4 的 43.4% 同样只适用于当前模型、batch 和软件栈。

### 3. 两机 16×H20 没有线性扩展

| H20 数量 | token/s 中位数 | 相对 2 卡 | 强扩展效率 |
|---|---:|---:|---:|
| 2 | 3,163 | 1.00× | 100% |
| 8 | 9,095 | 2.87× | 71.9% |
| 16 | 12,987 | 4.11× | 51.3% |

日志确认 16 卡跨两台宿主机，并出现 RoCE/GDRDMA 通道。效率下降不能只归因于网络，因为每卡工作量也随固定 global batch 扩卡而降低。

### 4. H20 与 910B4 都通过确定性恢复

连续训练 6 步，与“3 步保存、启动新进程、再训练 3 步”进行比较。两种硬件各自在本硬件内实现：

- 加载后的参数和 Adam 与保存点逐字节一致；
- 恢复后的最终参数和 Adam 与连续训练逐字节一致；
- 最终验证 loss 一致。

恢复只覆盖相同设备、软件栈和 world size 的 optimizer step 边界。它没有验证断电、节点丢失、部分 HDFS 写入或改变卡数。

## 可以回答什么

本实验支持以下结论：

- 动态 padding 是这批短样本最主要的吞吐和显存改进；
- selected 输出层能在保持目标一致的情况下进一步省显存；
- 延迟梯度同步明确减少通信次数，但以未分片梯度显存为代价；
- 1.5B 模型在 16×H20 上得到 4.11× 强扩展，效率为 51.3%；
- H20 和 910B4 均完成受控、确定性的状态恢复。

它不能证明模型能力提升、千卡可扩展性、生产级弹性恢复或新的训练算法。
